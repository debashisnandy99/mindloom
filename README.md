# Mindloom

A NotebookLM-style research workspace. Sign in with OAuth, create **notebooks**,
add **sources** (PDF / URL / YouTube / Google Doc / pasted text), and Mindloom
indexes them into a per-notebook vector collection so they can be queried and
turned into study **tools** — mind map, quiz, concept table, flashcards,
summary, audio overview, and timeline.

This is a Bun **monorepo** with two workspaces:

| Package | Path | Stack |
| --- | --- | --- |
| `mindloom` (client) | [`client/`](client/) | React 19, Vite 7, TypeScript, Redux Toolkit, TanStack Query, React Router 7, SCSS |
| `mindloom-server` (server) | [`server/`](server/) | Node 20+, Express 4, Prisma 7 (Postgres), BullMQ + Redis, Qdrant, OpenAI embeddings, S3 |

Deeper docs live next to the code:
[client architecture is in the source layout below](#repository-layout),
the server has a full [`server/README.md`](server/README.md) and
[`server/ARCHITECTURE.md`](server/ARCHITECTURE.md).

## Architecture

Two Node processes (API + indexing worker) share one `server/src` tree and
communicate **only through Redis and Postgres** — never in memory. The React SPA
talks to the API over REST and receives live indexing progress over SSE.

```
                              ┌──────────────────────────────┐
                              │         Client (SPA)         │
                              │  React 19 + Vite + Redux +   │
                              │  TanStack Query              │
                              └───────┬───────────────▲──────┘
                       REST /api/v1   │               │  SSE (EventSource)
                    (fetch, cookies)  │               │  /notebooks/:id/events
                                      ▼               │
   ┌──────────────────────────┐              ┌────────┴─────────────────┐
   │       API process        │   BullMQ     │      Worker process      │
   │    (src/index.ts)        │   (jobs)     │ (workers/indexing.worker)│
   │  Express: REST + SSE      │─────────────▶│  extract → chunk →       │
   │  enqueues indexing jobs   │              │  embed → upsert          │
   │  subscribes to progress   │◀─────────────│  publishes progress      │
   └───┬───────┬───────┬───────┘  Pub/Sub     └───┬────────┬────────┬────┘
       │       │       │          (events)        │        │        │
       ▼       ▼       ▼                          ▼        ▼        ▼
   ┌───────┐┌────────┐┌────────┐              ┌────────┐┌──────┐
   │ Redis ││Postgres││ Qdrant │              │ OpenAI ││  S3  │
   │queue +││ Prisma ││vectors │              │ embed  ││ PDFs │
   │session││ (truth)││(per nb)│              └────────┘└──────┘
   │pub/sub│└────────┘└────────┘
   └───────┘
```

**Why the split:** chunking, embedding (network calls to OpenAI), and S3
uploads are slow. Keeping them in a dedicated worker means `POST /sources`
returns `202 Accepted` immediately and the API event loop stays responsive
while a large PDF indexes in the background. Progress reaches the browser via
Redis pub/sub → SSE fan-out because the work happens in a different process than
the one holding the browser's connection.

### Indexing pipeline

```
POST /notebooks/:id/sources
  ├─ PDF?  → upload to S3   → content = S3 object URL
  └─ else  → content = URL / raw text
  → Source row (PENDING) → enqueue BullMQ job → 202 Accepted
                                    │
        worker: extract ▸ chunk ▸ embed ▸ upsert to Qdrant ▸ status = INDEXED
                                    │
              publish progress ─▶ Redis ─▶ SSE ─▶ browser progress bar
```

See [`server/ARCHITECTURE.md`](server/ARCHITECTURE.md) for the request
lifecycle, extraction per source type, the tool-CRUD factory, the Prisma data
model, and graceful-shutdown behaviour.

Study tools are generated by an LLM on a **second BullMQ queue** and RAG
questions are answered with query rewriting, RRF fusion, a relevance threshold,
and cited, grounded generation (streamed over SSE). See
[`server/README.md`](server/README.md) and
[`server/ARCHITECTURE.md`](server/ARCHITECTURE.md) for the full retrieval and
generation flow.

## Prerequisites

- **Bun** (package manager and script runner) — <https://bun.sh>
- **Docker** + Docker Compose (for local Redis and Qdrant)
- **PostgreSQL** database (managed e.g. Neon, or local) — set via `DATABASE_URL`
- **OpenAI API key** (embeddings), **AWS S3** bucket (PDF storage), and
  **Google / GitHub OAuth** apps for sign-in

## Run locally

From the **repository root**:

```bash
# 1. Start infrastructure (Redis + Qdrant)
docker compose up -d

# 2. Install all workspace dependencies
bun install

# 3. Configure environment
cp server/.env.example server/.env    # fill in DB, OpenAI, S3, OAuth secrets
cp client/.env.example client/.env    # defaults to http://localhost:3000

# 4. Set up the database schema
bun run --filter mindloom-server db:migrate
```

Then start the three dev processes (separate terminals, or use `dev:all`):

```bash
# Terminal A — API on http://localhost:3000
bun run --filter mindloom-server dev

# Terminal B — indexing worker
bun run --filter mindloom-server dev:worker

# Terminal C — client on http://localhost:5173
bun run --filter mindloom dev
```

Or run both server processes together:

```bash
bun run --filter mindloom-server dev:all
```

Open the client at **http://localhost:5173**. It calls the API at the base URL
in `client/.env` (`VITE_API_URL`) and appends `/api/v1` itself.

### Repo-wide scripts

Run from the root:

```bash
bun run typecheck    # typecheck server, then client
bun run lint         # lint the client
```

Husky + lint-staged run `precommit` checks on staged files automatically.

## Client architecture

- **Entry** ([`main.tsx`](client/src/main.tsx)) wraps the app in `QueryProvider`
  (TanStack Query) and `MindloomProvider` (Redux Toolkit).
- **Routing** ([`router.tsx`](client/src/router.tsx)) uses React Router 7 with a
  lazy-loaded route per page and a `ProtectedRoute` guard around
  `/notebooks` and `/workspace/:notebookId`.
- **Data fetching** — TanStack Query hooks in `hooks/queries` and
  `hooks/mutations` sit on top of a typed `api/` layer and a shared
  `lib/apiClient` (cookie-based auth, CSRF handling).
- **Live updates** — `lib/sseClient` + `hooks/events` subscribe to the API's SSE
  stream to render live source-indexing progress; `lib/streamClient` handles
  streamed answers.
- **Local UI state** — Redux Toolkit (`store/slices`, `store/thunks`) for
  cross-cutting UI state (theme, overlays, workspace context).

## Production & deployment

The production stack is defined in [`compose.prod.yaml`](compose.prod.yaml) and
deployed by the [`Jenkinsfile`](Jenkinsfile): CI builds and pushes the
`mindloom-client` and `mindloom-server` images, then the stack pulls and runs
them over SSH. It brings up Redis + Qdrant locally, runs Prisma
`migrate deploy` as a one-shot, and starts the API, worker, and client (behind
the host's nginx). Postgres is expected to be an external managed DB via
`DATABASE_URL`. See [`deploy/`](deploy/) for the nginx config and the production
env template.

To build the images locally:

```bash
docker build -f server/Dockerfile -t mindloom-server .
docker build -f client/Dockerfile -t mindloom-client .
```
